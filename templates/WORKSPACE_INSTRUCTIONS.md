# 工作区全局规则

## 🎯 Skill 自动触发规则

### intent-clarification

**什么时候触发：** 用户请求模糊、有多种理解、或涉及高风险决策时，**先调用这个 skill 澄清意图，再开始执行**。

触发条件：
- 模糊目标："我想做个..." / "我在考虑..." / "我需要..."
- 需要分解："不知道怎么..." / "不确定从哪开始..." / "需要帮我分析..."
- 多种合理理解：同一句话可能有 3+ 种不同的理解
- 高风险决策：涉及金钱、法律、健康、职业、商业、长期承诺
- 跨领域：用户明确说"完全不懂这个领域"

**不要触发：**
- 简单事实问题："现在几点？" / "Python 怎么读文件？"
- 明确的执行请求："帮我写个函数" / "修复这个 bug"
- 聊天确认："好的" / "继续" / "谢谢"

**灰色地带（根据上下文判断）：**
- "我想学 X"：完全新手 → 触发；有相关背景 → 简化
- "帮我评估这个想法"：触发（需要明确目标）
- "这个项目怎么做"：复杂项目 → 触发；小功能 → 不触发

**如何使用：**
检测到符合条件时，立即调用 `skill("intent-clarification")`，按照 skill 的工作流澄清用户真实意图后再继续。

---

### causal-factor-analysis

**什么时候触发：** 目标已经明确，但用户需要深度理解"为什么"和"如何影响"时，调用这个 skill。

触发条件：
- 目标已确认，但用户需要理解因果关系
- 陌生领域需要因果分析
- 重大决策需要清晰的因素分解
- 需要评估多个选项的权衡
- 用户问"我需要注意什么" / "关键因素是什么"

**如何使用：**
意图澄清完成后（或目标本身已经清晰），调用 `skill("causal-factor-analysis")` 识别并深度分解决定性因素。

---

### 协同工作流程

1. 用户输入模糊 → 先用 `intent-clarification` 澄清
2. 意图明确后 → 用 `causal-factor-analysis` 深度分解
3. 最后 → 根据分析结果执行/研究/规划

**示例：**

```
用户："我想做个任务清单管理 skill"

❌ 错误做法：直接去 GitHub 搜索项目
✅ 正确做法：
  1. 先调用 skill("intent-clarification")
  2. 列出 2-4 种可能理解：
     A. 任务提醒（定时提醒未完成任务）
     B. 对话交接（防止上下文漂移）
     C. 任务日志（记录已完成工作）
     D. 任务依赖管理（多任务协调）
  3. 问一个关键问题确认方向
  4. 用户确认后再继续
```
