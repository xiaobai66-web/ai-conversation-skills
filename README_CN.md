# AI 意图技能

**两个技能，帮助 AI 在行动前搞清楚用户真正想要什么。**

别让 AI 瞎猜浪费你时间。

---

## 问题

你说 **"我想买股票"**

AI 可能理解成：
- 教我基础知识（学习）
- 推荐具体股票（执行）
- 帮我开户（设置）
- 判断现在是不是好时机（咨询）
- 分析这个想法是否靠谱（验证）

**如果 AI 猜错了，整个对话就偏了。**

你说 **"我想做 AI 电商"**

AI 可能马上给你方案，但：
- 不解释*为什么*某些方向可行
- 不告诉你*什么时候*这个建议会失效
- 不区分事实和猜测
- 不告诉你怎么快速验证

**你可能学几个月才发现根本不可行。**

---

## 解决方案

两个独立的技能，配合使用：

### 1. 意图澄清
**做什么：** 回答前先搞清楚你到底想干什么。

- 列出 2-4 个可能的理解
- 展示每个理解的依据
- 问*一个*关键问题确认方向
- 形成"暂定目标"，你随时可以纠正

**何时用：** 你的请求模糊、有多种理解，或涉及高风险决策。

[查看技能 →](skills/intent-clarification-codex.md)

### 2. 因果分析
**做什么：** 拆解"什么决定成败"并深度解释。

- 识别决定性因素（真正会改变结果的）
- 解释*为什么*和*如何影响*，不只是*是什么*
- 用具体例子让你能想象实际场景
- 标注什么是事实 vs 假设 vs 未知
- 告诉你*什么时候*建议会失效
- 给你最小化验证方案

**何时用：** 目标明确但你不懂这个领域，需要评估可行性，或做商业决策。

[查看技能 →](skills/causal-factor-analysis-codex.md)

## 它们如何配合

```
你："我想买股票"
    ↓
意图澄清：
  "我想到 4 种可能... 哪一种？"
    ↓
你："我想先学习，然后买一点试试"
    ↓
因果分析：
  "这些因素决定成败：
   - 市场选择（为什么：影响监管、成本...）
   - 风险承受（为什么：决定仓位大小...）
   - 开户流程（为什么：影响速度...）
   
   每个因素都包含：
   ✅ 已知什么
   ❓ 未知什么
   ⚠️ 假设什么
   🔄 什么情况下改变"
```

## 真实案例

### 股票投资
- **输入：** "我想从零学会怎么买股票"
- **意图澄清：** 列出 4 种理解，确认用户既想学*也*想实际买
- **因果分析：** 拆解市场选择、风险承受、开户流程的完整因果链
- **结果：** 用户从模糊想法到清晰路径，一次对话搞定
- **评分：** 9.0/10（解释阶段有些偏航）

### Agent 配置
- **输入：** "到处都在讲 agent 教程，感觉我需要规范化用法"
- **意图澄清：** 列出 4 种可能（学方法、解决痛点、搭建系统、评估 ROI）
- **因果分析：** 深入拆解 agent 机制、工作文件夹设计、交接技能、维护成本
- **结果：** 用户从"完全不懂"到完全理解，一次对话搞定
- **评分：** 9.66/10

## 安装

### 第 1 步：复制 Skill 文件

**Codex 用户：**
```bash
复制 skills/intent-clarification-codex.md 和 skills/causal-factor-analysis-codex.md 
到你的 Codex 技能文件夹
```

**Harness 用户：**
```bash
复制 skills/intent-clarification-harness.md 和 skills/causal-factor-analysis-harness.md 
到你的 Harness 技能文件夹
```

两个版本功能完全一样，只是格式不同（YAML frontmatter vs markdown 标题）。

### 第 2 步：启用自动触发（推荐）

**不想每次都手动说 `skill("intent-clarification")`？**

在你的工作目录创建或更新 `WORKSPACE_INSTRUCTIONS.md`：

```bash
# 复制模板到你的工作目录
cp templates/WORKSPACE_INSTRUCTIONS.md /你的工作目录/
```

或直接从 [templates/WORKSPACE_INSTRUCTIONS.md](templates/WORKSPACE_INSTRUCTIONS.md) 复制内容。

**工作原理：**
- Harness 在每次对话开始时自动读取 `WORKSPACE_INSTRUCTIONS.md`
- AI 会根据里面的规则判断是否需要调用 skill
- **立即生效**，不需要重启或重新构建

**效果：**
- ✅ 你说"我想做个任务管理 skill" → AI 自动调用 `intent-clarification`
- ✅ AI 列出 2-4 种可能理解，问你确认
- ✅ 确认后再继续执行

详细配置见 [Harness 集成指南](docs/harness-integration.md)。

## 为什么分成两个技能？

**不同的工作，不同的触发时机：**

**意图澄清：**
- 触发：用户说话模糊或有歧义
- 输出：确认后的暂定目标
- 深度：刚好能确认方向

**因果分析：**
- 触发：目标明确但用户不懂这个领域
- 输出：深度因果拆解 + 验证方案
- 深度：决定性因素的完整解释

合在一起会让两个都半生不熟。分开后各自做好自己的事。

## 有什么不同

### vs. 普通追问
大多数 AI 只是问更多问题。这些技能*展示*给你 AI 是怎么理解你的话的，你可以早点纠正误解。

### vs. 标准任务拆解
标准拆解给你步骤。这个给你*因果关系*：为什么每个因素重要、如何影响结果、什么时候不重要。

### vs. GitHub 项目（Rasa, PMAgent, TypeChat 等）
我们研究了 6+ 个项目。没有一个做完整流程：
- **Rasa：** 有候选排序 + 置信度，但不让你选
- **PMAgent：** 有选项式提问，最接近，但只针对 PM 场景
- **TypeChat：** 有结构化确认，但没有概率排序
- **UAP：** 有不确定性采样，但不给用户展示候选

[查看完整对比 →](docs/comparison.md)

**我们的组合：**
- 候选排序（来自 Rasa）
- 用户选择（我们的创新）
- 因果解释（我们的创新）
- 暂定目标（我们的创新）
- 反转条件（我们的创新）
